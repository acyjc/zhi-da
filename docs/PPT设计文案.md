## Slide 9 · 技术创新点

```
┌──────────────────────────────────────────────────────────┐
│                  六大技术创新                               │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  1. Planner-Skill-Tool 三层智能体架构                      │
│     状态驱动决策 → 动态选择 Skill → 工具调用                 │
│     比传统 if-else 路由更灵活，比纯 Agent 更可控              │
│                                                          │
│  2. 双引擎诊断 Pipeline                                   │
│     确定性算法（规则+权重计算）+ LLM 语义理解                 │
│     5 步流式 Pipeline：画像→匹配→差距→路径→建议              │
│                                                          │
│  3. 规则/LLM 双审证据机制                                   │
│     规则引擎做硬约束校验 + LLM 做语义质量判断                 │
│     中英文混合分词，支持长文本证据                           │
│                                                          │
│  4. SSE 流式进度推送                                       │
│     Pipeline 每步实时通知前端，用户可感知 AI 处理进度          │
│     非流式意图自动降级，避免无效等待                          │
│                                                          │
│  5. Fallback 分级降级                                      │
│     LLM API 异常 → 自动切换规则模式                         │
│     系统不因 LLM 不可用而完全瘫痪                            │
│                                                          │
│  6. AI 能力边界三层管控                                     │
│     Capability 清单 → Intent 分类 → Tool 白名单            │
│     防止 LLM 越权操作，确保安全可控                          │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

**设计要点**：六宫格或列表布局，每项配一个图标。关键名词用蓝色高亮。

## Slide 10 · 技术亮点深挖 — 智能体架构

```
┌──────────────────────────────────────────────────────────┐
│       Planner-Skill-Tool：为什么不用 LangChain Agent？      │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  传统 Agent 方案              我们的三层架构               │
│  ┌─────────────────┐        ┌─────────────────┐         │
│  │  LLM 自由调用工具 │        │  Planner 状态决策 │         │
│  │  不可预测        │        │  确定性路由       │         │
│  │  容易越权        │        │  Skill 封装执行   │         │
│  │  成本高          │        │  Tool 白名单约束  │         │
│  └─────────────────┘        └─────────────────┘         │
│                                                          │
│  核心设计：                                               │
│  · 8 种意图分类（diagnose/re_evaluate/ask/continue_growth...）│
│  · 8 个 Skill 注册（每个 Skill 绑定 Tool 白名单）           │
│  · 7 个 Tool 实现（数据查询/状态变更）                       │
│  · LLM 仅用于语义理解（分类/审核/回答），不参与流程路由        │
│                                                          │
│  优势：可解释、可预测、可审计、低成本                          │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

**设计要点**：左右对比布局，左侧红色调（传统方案的问题），右侧绿色调（我们的方案的优势）。

## 附：答辩准备建议

### 时间分配（假定 15 分钟）

| 环节 | 时长 | 对应 Slide |
|------|------|-----------|
| 开场 + 背景 | 2 min | 1-3 |
| 产品定位 + 架构 | 2 min | 4-5 |
| 核心功能演示 | 5 min | 6-8 + 现场 Demo |
| 技术创新 | 3 min | 9-11 |
| 测试 + 价值 | 2 min | 12-14 |
| 总结 + 致谢 | 1 min | 15-16 |

### 关键答辩话术准备

1. **"为什么不用 LangChain Agent？"** → Slide 10：可控性优于灵活性
2. **"LLM 挂了怎么办？"** → Slide 9 第5点：Fallback 自动降级
3. **"和市面上的简历工具有什么区别？"** → 不是简历工具，是 AI 成长闭环
4. **"数据安全怎么保证？"** → JWT 认证 + 学生主动授权 + 数据最小化
5. **"怎么证明真的有效？"** → 复评前后能力变化量化 + 204 测试 100% 通过

### 设计风格统一建议

- **主色调**：深蓝 (#1a365d) 渐变至科技蓝 (#0071e3)
- **强调色**：暖橙 (#ff9500) 用于数据高亮
- **字体**：标题用思源黑体 Bold，正文用思源黑体 Regular
- **背景**：纯白底 + 蓝色几何装饰元素（圆角矩形、渐变线条）
- **图表**：统一的圆角、阴影、配色方案
