# 职达 V2 下一轮可信 MVP 改进方案

> 日期：2026-06-01  
> 目标：将当前“可演示 MVP”升级为“可信、可持续使用的 MVP”  
> 原则：先消除误导和状态不一致，再增强智能体体验，最后补充视觉微交互。

## 一、对外部审查报告的评估

外部报告适合作为补充检查清单，但不能直接作为下一轮 Roadmap。它识别出若干真实问题，同时高估了当前产品完成度，并遗漏了更影响用户信任的实现缺口。

### 1.1 采纳项

| 报告意见 | 结论 | 处理方式 |
|---|---|---|
| 小喵绕过统一 API 实例 | 合理 | 将聊天请求纳入统一 API 模块，为超时、鉴权和网关配置预留一致入口 |
| 诊断完成后无条件切回首页 | 合理 | 用户已手动切换 Tab 时只提示数据已更新，不强制跳转 |
| 首页任务完成状态仅保存在局部组件 | 合理且高优先级 | 从后端进度接口回填任务状态，Tab 切换和刷新后保持一致 |
| 清理学校端课程管理残留和手工推荐死代码 | 合理 | 删除不可达前端代码，并删除学校手工推荐 API |
| 小喵需要页面上下文 | 合理 | 作为智能体体验增强主线落地 |

### 1.2 需要修正的判断

| 报告意见 | 修正 |
|---|---|
| “已建立多源可信证据墙” | 尚未建立。当前证据墙、置信度、GitHub 扫描结果和企业评价均为前端静态文案，必须删除或接入真实数据 |
| “已闭环三方投递授权流” | 只完成了部分闭环。岗位审核可触发自动创建机会，但仍沿用 `recommended` 状态和学校推荐接口 |
| “SSE 网络拆包会直接导致 JSON.parse 崩溃” | 当前 buffer 已能处理普通 TCP 分片。真实风险是解析异常被静默丢弃、末尾未完整事件未明确报错、缺少标准事件分隔处理 |
| “growth.py 是空路由，可删除” | 不成立。该路由提供成长记录查询，且已有冒烟测试覆盖，应保留 |
| “Dev Console 是产品核心体验” | 仅适合作为开发和演示辅助能力。必须通过开发环境开关启用，不进入正式用户界面 |

## 二、本轮范围

本轮聚焦四个结果：

1. 页面不再展示伪造证据、伪造指标或旧“学校推荐”叙事。
2. 系统自动匹配、学生授权、企业反馈使用统一且可追踪的状态机。
3. 学生任务和证据真实持久化，Tab 切换与刷新后不丢失。
4. 职达小喵能够读取学生上下文，给出与当前页面相关的建议。

以下内容暂不作为本轮主线：

- 完整视觉重构
- 复杂动画和游戏化效果
- 完整生产级多租户权限系统
- 大规模资源推荐算法

但在进入真实试点前，必须增加基础登录、角色鉴权和企业数据隔离。

## 三、实施阶段

### 阶段 0：可信度清理与部署基线

#### 目标

先移除会误导用户的内容，保证本地和容器环境一致可运行。

#### 改动

- 将 Docker SQLite 数据卷保持在 `/app/data`，禁止覆盖 `/app/db` Python 包。
- 删除首页中的“学校推荐人才”“经学校推荐”“授权推荐”等旧文案。
- 删除学校端不可达的课程管理状态、请求和表单代码。
- 删除学校端 `handleRecommend`、`recommendTalent` 和 `/api/school/applications` 手工创建入口。
- 删除前端静态证据墙、静态置信度、伪 GitHub 扫描记录、伪企业评价。
- 删除差距侧边栏中的硬编码 GitHub 仓库、静态 AI 解释和固定收益比例。
- 学校和企业后台缺失字段统一展示“未填写”，禁止伪造 `2022级`、默认专业和默认姓名。
- 学校能力缺口图、企业岗位完整度如果暂无真实数据，展示明确空状态，不展示固定演示值。

#### 验收

- 全局搜索不再出现 `推荐校内优秀毕业生`、`github.com/ccnnd`、固定证据墙文案。
- 页面不再将前端静态模板标记为 AI 结果。
- `docker compose up -d --build` 后前后端容器保持 `Up`。

### 阶段 1：真实机会状态机

#### 目标

跑通无需学校手工干预的最小机会闭环。

#### 状态机

```text
matched
├── authorized → viewed → interviewed → hired
│                              └──────→ declined
└── ignored
```

#### 改动

- 数据库默认状态由 `recommended` 改为 `matched`。
- 岗位审核通过后由系统创建 `matched` 机会和 `matched` 事件。
- 学生端只处理 `matched` 机会，可授权或暂不考虑。
- 企业端只展示学生已授权后的候选人。
- 企业查看候选人时记录 `viewed` 事件。
- 企业反馈统一使用 `interviewed`、`hired`、`declined`。
- 为已有 SQLite 数据增加兼容迁移：

```text
recommended → matched
rejected（学生侧）→ ignored
rejected（企业侧）→ declined
```

- 事件记录统一标记 `operator_role`：`system`、`student`、`enterprise`。

#### 验收

- 企业发布岗位 → 学校审核 → 系统匹配 → 学生授权 → 企业查看 → 企业反馈，全流程无需学校手工推荐。
- 每次状态变化均有事件记录。
- 企业无法看到未授权学生。

### 阶段 2：任务与证据持久化

#### 目标

让成长路径从一次性展示变成学生可以持续使用的工具。

#### 数据模型

新增 `growth_tasks`：

```text
id
student_id
diagnosis_id
source_type(gap|feedback|advisor|manual)
source_ref_id
title
description
steps
resource_links
evidence_requirement
skill_impact
estimated_minutes
estimated_gain_range
status
created_at
updated_at
```

新增 `student_evidence`：

```text
id
student_id
task_id
evidence_type(resume|project|course|certificate|task|enterprise_feedback)
title
content
source_url
skill_mapping
confidence
verified_status
created_at
```

#### API

```text
GET  /api/students/{id}/tasks
POST /api/students/{id}/tasks
POST /api/students/{id}/tasks/{task_id}/evidence
GET  /api/students/{id}/evidence
```

#### 改动

- 诊断生成的路径任务写入 `growth_tasks`。
- 差距侧边栏只展示后端生成的任务草案；用户确认后持久化。
- 首页和路径页统一读取任务 API，不再使用局部 `completedList` 判断真实状态。
- 提交证据后先进入 `submitted`，核验后进入 `verified`；不再点击按钮就直接增加技能分。
- 能力画像只展示真实证据和真实置信度；缺少证据时展示“待补充证据”。
- 企业拒绝反馈可生成任务草案，但必须由学生确认后加入计划。

#### 验收

- 切换 Tab、刷新页面和重新打开浏览器后，任务状态保持一致。
- 未提交证据的任务不能提升能力分。
- 每个能力分都能追溯到真实证据或明确显示证据不足。

### 阶段 3：职达顾问上下文化

#### 目标

让用户明确感知这是一个理解自己当前状态的智能体，而不是通用聊天框。

#### API

```text
POST /api/students/{id}/advisor
```

请求：

```json
{
  "scene": "workspace|profile|plan|opportunities|growth",
  "messages": []
}
```

后端自动拼装：

```text
学生画像
主目标和备选方向
高优先级差距
本周任务
任务证据
自动匹配机会
企业反馈
当前页面场景
```

#### 改动

- 小喵改用统一 API 模块。
- 快捷问题根据 `scene` 动态生成。
- 首页只展示一条最值得执行的主动建议。
- 能力差距较大时提供“方向探索”入口，不强迫学生只沿单一岗位补差距。
- 保留顾问页作为完整对话空间，小喵只承担轻量提醒。

#### 验收

- 在画像页询问“我最该补什么”，回答包含学生真实差距。
- 在路径页询问“本周做什么”，回答包含真实任务。
- 在机会页询问“值得投哪个”，回答引用真实机会及匹配依据。

### 阶段 4：可靠性与体验收口

#### 改动

- SSE 解析改为标准事件分隔处理，解析异常给出明确错误，不静默吞掉非法事件。
- 诊断完成时，如果用户已手动切换 Tab，只弹 Toast，不强制切回首页。
- 增加仅开发环境可见的 Sandbox 开关，用于清理本地会话和切换演示身份。
- 首页大标题调整断行，避免单字独占一行。
- 按学生、学校、企业路由拆包，图表按需加载，降低首屏包体积。

#### 验收

- SSE 单元测试覆盖分片、CRLF、非法 JSON、缺少 result 事件。
- 诊断期间手动切换 Tab，完成后不打断用户操作。
- 生产构建中不显示 Sandbox。
- 首屏包体积明显低于当前约 `1.43 MB`。

## 四、建议开发顺序

| 顺序 | 工作项 | 原因 |
|---|---|---|
| 1 | 清理伪数据、旧文案和学校手工推荐入口 | 直接影响用户信任，改动范围清晰 |
| 2 | 将机会状态机统一为 `matched` | 为真实三方闭环建立稳定基础 |
| 3 | 完成任务与证据持久化 | 学生端留存价值的核心 |
| 4 | 小喵上下文化 | 让智能体能力可被用户感知 |
| 5 | SSE、Tab 跳转、拆包和视觉收口 | 在核心逻辑可信后提升稳定性与体验 |

## 五、产品验收脚本

使用一个学生、一家企业和一个岗位完成完整流程：

```text
学生上传简历
→ 系统诊断并生成画像、差距和任务草案
→ 企业粘贴 JD 并确认岗位能力模型
→ 学校审核岗位
→ 系统生成 matched 机会
→ 学生查看匹配依据并授权
→ 企业查看脱敏候选人
→ 企业填写“Docker 经验不足”并拒绝
→ 学生收到反馈和 Docker 任务草案
→ 学生确认任务并提交证据
→ 系统核验证据
→ 画像、匹配度和成长轨迹更新
→ 小喵能够解释本次变化依据
```

该脚本完整跑通后，职达才具备可供小范围真实用户试用的可信 MVP。
