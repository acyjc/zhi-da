### Tab 6：成长追踪 —— 从"V1对V1无意义对比"到"真实的多版本趋势"

**根因分析（代码追溯）**

```typescript
// Dashboard.tsx:182-183  —— handleReEvaluate 中
if (diagnosisResult) {
    setDiagnosisHistory([...diagnosisHistory, diagnosisResult])  // 手动push旧结果
}

// Dashboard.tsx:202-208  —— useEffect 自动触发
getDiagnosisHistory(student.id)
    .then((data: DiagnosisResult[]) => setDiagnosisHistory(data))  // 又从后端拉，覆盖了
```

**问题链条**：
1. 再诊断完成后，前端手动 push 旧 result 到 history（临时状态）
2. 紧接着 `useEffect` 又从后端拉取 `getDiagnosisHistory`
3. 后端只存储一个 `DiagnosisORM` 的 `version` 字段，初始为 1
4. 再诊断时如果后端没有正确调用 `version = latest + 1`，则所有记录都是 V1

**改造方向**

```
┌─────────────────────────────────────────────────────────────┐
│  成长趋势                                                   │
│                                                             │
│  100% ┌────────────────────────────────                    │
│   80% │      ●技术能力                                      │
│   60% │  ●───●软技能                                        │
│   40% │      ●项目经验                                      │
│   20% │  ●───     ●领域知识                                  │
│    0% └┬──────┬──────┬──────┬──────┬                       │
│       V1     V2     V3     V4     V5                       │
│       4/15   4/22   5/1    5/15   5/30                     │
│                                                             │
│  ▸ 最近变化（V4 → V5）                                      │
│    技术能力 +12%  软技能 +6%  项目经验 -2%  ← 自动取最近     │
│                                                             │
│  ▸ 诊断时间线                                               │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ ● V5 5/30  85% 再诊断（完成任务后）                  │   │
│  │ ○ V4 5/15  78% 再诊断                                │   │
│  │ ○ V3 5/1   72% 完成任务：Python高级特性               │   │
│  │ ○ V2 4/22  70% 再诊断                                │   │
│  │ ○ V1 4/15  68% 首次诊断                               │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

**需要修改**
- 后端 `diagnosis_pipeline.py`：确保每次诊断/再诊断后 `version` 自增
- 前端移除手动 push history 逻辑，只从后端读
- GrowthTab：移除手动"版本对比选择器"，改为自动展示"最近一次变化摘要"（latest vs previous）
- 时间线改为纵向展示（X轴=日期，Y轴=4条维度线）

## 四、信息架构重设计

### 当前信息流（单向+孤立）

```
Profile → 只看标签分数
Match   → 只看仪表盘和柱状图
Path    → 只看任务列表
Advice  → 只看一段文字
Recommend→只看5张卡片
Growth  → 只看趋势图+V1对比V1
```

每个 Tab 是孤岛，没有横向关联。

### 目标信息流（交叉引用）

```
         ┌──────────────┐
         │  能力画像     │ ← 雷达图 + AI评语 + 技能热力图
         │  (统领全局)   │
         └──┬───────┬───┘
    差距数据 ↓       ↓ 技能标签
    ┌──────┴──┐  ┌──┴─────────┐
    │ 岗位匹配 │  │  职业建议   │ ← 差距→建议★
    │  匹配度  │  │  技能→方向  │
    └──┬──────┘  └──────┬──────┘
       │                │
       ↓                ↓
    ┌──────────┐  ┌──────────┐
    │ 就业推荐  │  │ 成长路径  │ ← 方向→规划★
    │ 岗位画像  │  │ 目标→任务  │
    └──────────┘  └────┬─────┘
                       ↓ 完成任务
                  ┌──────────┐
                  │ 成长追踪  │ ← 版本递增 + 趋势★
                  │ 趋势线    │
                  └──────────┘
```
